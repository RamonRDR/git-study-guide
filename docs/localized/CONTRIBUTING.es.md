# Contribuir a Git Study Guide

[English](../../CONTRIBUTING.md) · [Português](CONTRIBUTING.pt-BR.md) · [Español](CONTRIBUTING.es.md)

## Antes de cambiar

Leer Constitution, hoja de ruta e instrucciones; buscar issues, describir una mejora y acordar alcance para cambios sustanciales. Cualquiera puede proponer cambios mediante fork y PR; solo colaboradores autorizados escriben en upstream. Nunca presumir permiso de merge.

## Flujo de contribución

1. Partir de main upstream actual en rama enfocada (ejemplo `docs/branch-explanation`).
2. Hacer cambios pequeños y originales; commits descriptivos en inglés como `docs: clarify branch references`.
3. Actualizar documentos EN/PT-BR/ES juntos, conservar rutas e identificadores.
4. Verificar fuentes, enlaces relativos, terminología, requisitos y ejemplos. Ejecutar solo pruebas seguras en repos desechables, informar comandos, resultados y omisiones.
5. Abrir PR con alcance, issue, evidencia, asistencia IA y riesgos; atender feedback y verificar última revisión.
6. Mantenedor aprueba explícitamente squash merge; nunca eludir protecciones.

## Calidad educativa y técnica

Explicar qué, por qué, uso/evitar, efectos, riesgo y recuperación antes de practicar. Enseñar principiantes sin términos sin explicar. Priorizar fuentes oficiales Git/plataformas y ejemplos originales. Separar Git nativo de GitHub/GitLab. Identificar versión, SO, shell y requisitos cuando correspondan. Sin material privado, secretos ni ejemplos propietarios. No ejecutar comandos destructivos en la guía. CI previsto para Sprint 02; no listar comandos inexistentes como aprobados. Luego usar checks documentados y ejemplos en allowlist.

## IA y licencias

Declarar asistencia de IA y verificar material personalmente; no enviar contenido generado sin revisión. Al contribuir, permitir distribución bajo licencia MIT del repositorio; conservar copyright y atribución compatible. Si autoría o permiso son inciertos, no enviar. Crédito individual queda en Git e historial de PR.
