# Repository instructions

[English](AGENTS.md) · [Português](docs/localized/AGENTS.pt-BR.md) · [Español](docs/localized/AGENTS.es.md)

## Purpose and authority

Git Study Guide is a free independent MIT educational guide. Assume no programming experience. Follow the approved constitution, specification and acceptance criteria. Prioritize technical accuracy, clarity, privacy and safety, locale parity, maintainability, then speed. If instructions conflict, stop and obtain maintainer resolution. Ramon Rodriguez is responsible for final direction and approvals.

## Languages and content

Update all affected public documents in English, Brazilian Portuguese and Spanish in the same PR. English is primary; technical paths, identifiers, code comments, branches, commits and schema keys stay English. Preserve MIT text and attribution. Teach objectives, prerequisites, why, effects, safe examples, risks, recovery, exercises and official sources; do not introduce unexplained terminology. Keep chapter paths stable and curriculum independent of Python or AI.

## Safety and examples

Create original fictional examples, never employer, client, personal or proprietary material, secrets or private URLs. Run risky commands only in disposable owned repositories, never in this guide. Use isolated Git config, fictional identity, local bare remotes and explicit state checks; no arbitrary student code in privileged CI. Distinguish native Git from hosting features. Verify version-dependent behavior against official docs. Never claim recovery is guaranteed.

## Workflow and evidence

Read current main and applicable SDD documents; confirm dependencies and scope. Create a focused branch from current main. Implement all locales, run applicable tests, check links, review changed files, inspect privacy, open PR. Verify latest SHA, actual CI and Codex review if available. Address relevant findings before resolving threads; rerun checks and record evidence. Obtain explicit maintainer approval before squash merge, verify main and branch deletion. Never push directly to main, bypass protections, merge on assumed approval, or invent results. If CI/review is unavailable, disclose it; no CI before Sprint 02 is an exception, not a pass.

## Scope and AI

AI may assist, never replace understanding or human review. Treat AI output as a proposal and verify sources, claims and translations. No paid services, required AI, website implementation, arbitrary privileged execution or semantic AI grading. Keep other repositories read-only unless separately authorized. Do not change administrative settings without approval. Update task evidence and disclose limits in each focused PR.
