# Security policy

[English](SECURITY.md) · [Português](docs/localized/SECURITY.pt-BR.md) · [Español](docs/localized/SECURITY.es.md)

## Scope

This is an educational repository, not a deployed service. Security fixes target current main and the latest maintained release if one exists. Historical commits, forks and third-party tools are not maintained here. Relevant risks include unsafe workflows, leaked credentials, compromised examples and reproducible unsafe guidance. Ordinary content bugs belong in normal issues.

## Private reporting

If the repository Security tab offers **Report a vulnerability**, use it for a private report. Its availability has not been verified; do not assume it is enabled. Otherwise use a private method published by the [maintainer](https://github.com/RamonRDR), or a [private contact request](https://github.com/RamonRDR/git-study-guide/issues/new?template=private-contact-request.md) solely to establish a channel. That issue is PUBLIC: never include vulnerability details, exploit steps, affected files, screenshots, secrets or personal/contact data. If the request itself risks disclosure, do not post it. No verified private fallback is guaranteed until the maintainer supplies a channel.

## Safe report and response

Once a private channel is established, provide affected revision/component, impact, minimal safe reproduction, environment and mitigation if known; never include real credentials or unauthorized data. Research only in authorized disposable environments: no disruption, credential theft, social engineering, access to others' data or destructive testing. The maintainer will triage on a best-effort basis, coordinate remediation and responsible disclosure, and credit reporters when requested and safe. No SLA, bounty or financial reward promised. Do not publicly disclose exploitable details while remediation is pending.
